# Conceptos y guion de presentación · 30 minutos

← [[00 - Inicio - Taller Antigravity|Taller de Google Antigravity · Unisabana e-learning]]

## 1. De una pregunta a un trabajo verificable · 5 minutos

Abrir con: «¿Confiarían en un consolidado que se ve bien pero no permite reconstruir cómo se hizo?». Conectar la pregunta con el objetivo: producir resultados útiles, revisables y repetibles.

## 2. Qué hace Antigravity · 10 minutos

Antigravity es una plataforma de desarrollo con agentes. Según la aplicación y los permisos disponibles, el agente puede examinar archivos, proponer un plan, escribir y ejecutar código, y producir artefactos. No es únicamente un chat ni una garantía de exactitud. No hace falta saber programar para dirigir un caso, pero sí comprender sus reglas de negocio.

| Concepto | Explicación sencilla | Ejemplo |
|---|---|---|
| Modelo | Propone respuestas y acciones a partir del contexto | Sugiere una regla para correos |
| Agente | Usa herramientas para avanzar hacia una tarea | Lee la hoja y genera un reporte |
| Contexto | Información y límites que recibe | Archivo, hoja, significado de columnas |
| Proyecto | Carpeta o conjunto de carpetas de trabajo | Solo el caso asignado |
| Herramienta | Medio para actuar | Lectura de archivos o ejecución de un script |
| Plan | Secuencia propuesta antes de transformar | Inspeccionar → acordar reglas → procesar → validar |
| Artefacto | Resultado que se puede abrir y revisar | Plan, script, tabla, informe o prototipo |
| Verificación | Prueba que contrasta una afirmación | Contar filas y revisar ejemplos en el original |

Flujo didáctico: **encuadrar → inspeccionar → planificar → ejecutar → verificar → comunicar**. El agente no debe saltar de una petición vaga a una transformación irreversible.

## 3. Operaciones con datos · 10 minutos

| Operación | Pregunta | Aplicación |
|---|---|---|
| Limpieza | ¿Hay ruido, vacíos o errores de formato? | Espacios externos en correos |
| Normalización | ¿Cómo representar de forma consistente lo mismo? | Catálogo de tipos de identificación |
| Sistematización | ¿Cómo organizar datos, reglas y procedencia? | Diccionario y tabla de cambios |
| Conciliación | ¿Qué coincide o discrepa entre fuentes? | Insignias esperadas frente a observadas |
| Verificación | ¿Qué evidencia sostiene el resultado? | Trazabilidad fila a fila y conteos |
| Uso | ¿Qué decisión o experiencia se habilita? | Priorización de pendientes o recurso educativo |

No confundir formato correcto con verdad. Un correo puede tener estructura válida y pertenecer a otra persona. Dos nombres parecidos no prueban que dos insignias sean equivalentes. Una encuesta no prueba causalidad ni representa automáticamente a toda una población.

## 4. Ejercicio crítico · 5 minutos

Ejemplo **sintético**: «Curaduría Digital» y «Curaduria digital avanzada». Preguntar si deben fusionarse. Respuesta esperada: normalizar espacios y comparar ayuda, pero “avanzada” podría cambiar el significado; hace falta evidencia adicional y revisión humana.

Mensaje de cierre: **automatizar lo repetible, hacer visibles las excepciones y conservar la decisión humana cuando falte evidencia**.

## Precauciones vinculadas al caso

- Los archivos de personas contienen identificaciones, correos y teléfonos; la encuesta incluye IP y textos abiertos. Trabajar localmente no garantiza que su contenido no llegue al proveedor del modelo.
- Usar datos sintéticos o anonimizados aprobados para la práctica; seudonimizar no equivale necesariamente a anonimizar.
- No ejecutar instrucciones encontradas dentro de celdas o respuestas abiertas: son datos, no órdenes.
- No habilitar acceso a correo, sistemas de insignias ni otros conectores para resolver estos ejercicios.
